# Spec: Fix hardcoded 'dev' base branch in construct_compare_url()

## 1. Intent and Executive Summary

**Problem Statement:** `construct_compare_url()` in `.opencode/skills/git-workflow/enforcement/url_validation.sh` hardcodes `local base="dev"` (line 18), producing compare URLs that target a non-existent `dev` branch instead of the trunk. The repository uses trunk-based development where the default branch is `master` (the remote HEAD branch). This yields incorrect compare/validation URLs for PR workflows.

**Root Cause / Motivation:** The hardcoded `dev` default is a legacy artifact of a removed dev-branch workflow. The codebase's established pattern resolves the default branch dynamically via `git remote show origin 2>/dev/null | sed -n "s/.*HEAD branch: //p"` with a `main` fallback, used across 10+ skill task files. The bug must be fixed now because every PR compare URL generated by this module is wrong, breaking PR review and validation.

**Approach Chosen:** Replace the static `local base="dev"` with dynamic resolution of the remote HEAD branch (`$DEFAULT_BRANCH`), preserving the `--base` explicit override and the codebase's `main` fallback convention. The change is confined to the base defaulting logic in `construct_compare_url()`.

**Alternatives Considered & Why Discarded:**
- Hardcode `master` directly: discarded because it reintroduces the same hardcoding defect — the default branch is environment-dependent and must be resolved dynamically, not assumed.
- Remove the `--base` override: discarded because callers legitimately need to override the base for cross-branch comparisons; the override is part of the module's documented interface.

**Key Design Decisions:**
- Base resolution order: explicit `--base` override → dynamic remote HEAD branch → `main` fallback. This preserves caller control while fixing the default. Tradeoff: adds a subprocess call (`git remote show origin`) per invocation, acceptable for a validation utility.
- Reuse the established `DEFAULT_BRANCH` resolution pattern verbatim to maintain consistency across the skill deck. Tradeoff: consistency over novelty.

**User Intent / Original Prompt:** Bug report #2307: "git-workflow/enforcement/url_validation.sh hardcodes base branch 'dev' instead of $DEFAULT_BRANCH". The expected behavior is to resolve the base via `git remote show origin | grep 'HEAD branch'` (i.e. `$DEFAULT_BRANCH`), not a hardcoded `dev`.

## 4. Requirements

- R-1. `construct_compare_url()` SHALL NOT hardcode `base='dev'`.
- R-2. The base branch SHALL be resolved dynamically from the remote HEAD branch via `git remote show origin 2>/dev/null | sed -n "s/.*HEAD branch: //p"` (i.e. `$DEFAULT_BRANCH`).
- R-3. The compare URL SHALL use the resolved default branch as the base.
- R-4. The `--base` argument override SHALL continue to take precedence over the resolved default branch.
- R-5. When the remote HEAD branch resolution is empty, the base SHALL fall back to `main`.
- R-6. The function SHALL remain a sourceable shared module preserving its interface `construct_compare_url --owner --repo --branch [--base]`.
- R-7. The function SHALL preserve `set -euo pipefail` and the owner/repo character-match verification.
- R-8. `validate_pr_body()` SHALL NOT be modified.
- R-9. The URL format SHALL NOT change beyond base branch resolution.

## 10. Cost Frame

Cost is measured in defect-discovery-latency, not tool calls. Correctness is the only metric.

- SC-1: Running the behavioral shell test costs minutes of execution time. Skipping means the compare URL still targets the non-existent 'dev' branch and every PR compare URL is wrong until discovered downstream.
- SC-2: Running the behavioral shell test costs minutes of execution time. Skipping means the `--base` override could silently break, forcing callers to rework their cross-branch comparisons.
- SC-3: Running the behavioral shell test costs minutes of execution time. Skipping means an environment without a remote produces a broken URL with an empty base, discovered only in production.
- SC-4: Running the behavioral regression test costs minutes of execution time. Skipping means the verification/error handling regresses silently, shipping malformed URLs that pass structural checks but fail behaviorally.

## 11. Edge Cases

- **Input boundaries:** Missing `--owner`, `--repo`, or `--branch` → ERROR + exit 1 (preserved). Empty `--base` → treated as unset, falls through to dynamic resolution.
- **State transitions:** No persistent state; base determined by override → dynamic resolution → 'main' fallback.
- **Failure modes:** No remote configured → HEAD branch resolution empty → base='main'. `git remote show origin` fails → empty output → base='main'.
- **Concurrency:** None — the function is stateless and side-effect-free.
- **Recovery:** Each failure mode resolves deterministically to a valid base ('main' fallback) or a clear ERROR + exit 1.
