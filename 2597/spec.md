# [REGRESSION] Local issue-record mirroring and the audit local-artifact gate lost in the #2490 re-rip

## 1. Intent and Executive Summary

| # | Field | Description |
|---|-------|-------------|
| 1 | **Problem Statement** | The deck's issue-record local-mirroring discipline and the audit local-artifact gate were lost in the #2490 re-rip. Observed 2026-10-13, two facets. **Facet 1:** `.opencode#2551` (a BUG report carrying its full incident analysis) was filed remotely with the header *"Local artifacts: `.opencode/.issues/2554/` on the `.opencode` issues-data worktree — the authoritative analysis lives there"* — pointing at the folder of the unrelated, closed Ainglish spec issue #2554. No `2551/` directory exists in the `.opencode` issues-data store, no commit in the store's history ever added one, and the issue carries no local binding. **Facet 2:** when the developer authorized `spec audit: .opencode#2551` on 2026-10-13, the agent found no local artifact, and the current deck's cards contain no mechanism that verifies a local artifact's presence before an audit or mandates mirroring the remote-tracked content when it is absent — so the audit died on a list of fail reasons about absence. The developer ruled those fail reasons fabricated: the repair (mirror the remote content into the local store, correct the pointer) was available fact work, not a blocker. |
| 2 | **Root Cause / Motivation** | The #2490 rip-and-replace retired the old audit machinery and the spec-creation create task wholesale. The attic evidence (audited 2026-10-13) shows what was lost: the retired `audit` skill's spec-audit entry criteria mandated the mirror — *"If the spec is only on GitHub (not locally mirrored), the orchestrator MUST mirror it as .md files in spec_local_dir/ first. Dispatching without a valid spec_local_dir is a CRITICAL VIOLATION"* (`attic/skills/audit/tasks/spec-audit-investigator.md`, Entry Criteria) — and the retired spec-creation create task enforced local == remote by construction, with an explicit renumber/migrate repair pattern for collisions and BLOCKED states instead of silent fallbacks (`attic/skills/spec-creation/tasks/create.md`, Steps 2–3 and the remote-first reservation mandate). The #2550 restoration rebuilt the validation verdict semantics and #2575 restored the automatic-fail rule, but neither restored the local-record construction guarantee, a repair path for a remote issue whose local record is absent, or the audit-side entry gate. |
| 3 | **Approach Chosen** | Amend the four cards that carry the affected moments, each with wording shaped to its own semantic context (per the developer's 2026-10-13 directive to determine the card set and adapt details per card). `.opencode/skills/issues/SKILL.md` — the store lifecycle owner — gains (a) a mirror-repair rule: on discovery that a remote issue's local record is absent or its local-artifacts pointer unresolvable, create the local record at the remote-assigned number via `local-issues create --number repo#N`, mirror the remote-tracked content into `{N}/`, and correct the remote body's pointer; (b) a creation-time pointer check: the local-artifacts pointer written into a remote issue body must resolve to the actual local folder at write time. `.opencode/skills/spec/SKILL.md` — the authoring side — gains the construction guarantee in its write-and-persist step: the remote body's local-artifacts pointer must resolve at write time, and a mid-flow local write failure BLOCKs the flow rather than leaving an unresolvable pointer. `.opencode/skills/verify/SKILL.md` — the audit dispatch side — gains an entry gate: an audit requires the audited artifact present at a verified local path; when absent, the auditor performs the mirror-repair per the issues card and proceeds; absence of a local artifact is never a fail reason or halt ground by itself. `.opencode/skills/plan/SKILL.md` — the pipeline consumer — gains one clause in its consume-validated-specs rule: consuming a spec whose local record is absent routes through the issues card's mirror-repair first. Record the restoration in the deck-debt ledger (#2534). |
| 4 | **Alternatives Considered & Why Discarded** | (a) Restoring the attic audit DiMo chain (Investigator → Validator → Evaluator → Arbiter) verbatim — discarded: the single-fresh-context-reviewer model is the #2550 restoration's deliberate shape; this item restores the artifact-presence gate, not the dispatch topology. (b) Restoring the attic spec-creation create task's full BLOCKED-state matrix — discarded: the current spec card's write-and-persist step already constructs the local record on creation; the regression is the repair path for records that were never created plus the unguarded pointer write, not the creation flow itself. (c) A retroactive sweep mirroring all historical remote issues that lack local records — discarded: forwards-only repair on discovery matches the deck's grandfathering posture; a sweep would touch hundreds of legacy issues with no observed-failure demand. (d) Restating the mirror mechanism in the `work` card alongside its "missing upstream artifacts trigger the pipeline, never reasons to halt" principle — discarded: the work card states the stage-level principle and other cards cite it; the mirror-repair mechanism is store-level detail owned by the issues card, and duplicating it would create a second copy that drifts. |
| 5 | **Key Design Decisions** | (1) The mirror-repair is fact work — mechanical, always performed on discovery, never narrated as a fail reason; the "fabricated fail reasons" defect is addressed structurally by making repair the required action, not by a rule against narration. (2) The repair binds the remote-assigned number — `local-issues create --number repo#N` — never a local-counter pick, inheriting the attic's remote-number-first invariant. (3) The pointer check is a fact-decidable file fact (does the named path exist at write time), not a judgment call. (4) The audit gate scopes to audits: a reviewer dispatched to audit consumes a local artifact; ensuring one exists is the auditor's own fact work, mirroring the attic's CRITICAL-VIOLATION framing. (5) Ticket-state hygiene (#2563, issues card §6) governs state divergence for an existing local record; the mirror-repair here governs the record's absence — the two govern different moments and do not collide, and the repair text cross-references §6 rather than duplicating it. (6) The per-card wording differs by design — the issues card states the full mechanical procedure (store owner), the spec card states the authoring-time resolution guarantee (construction side), the verify card states the dispatch gate and defers the mechanism to the issues card (consumer side), and the plan card carries a one-clause route-to-repair (pipeline consumer) — one mechanism, four moments, no duplicated procedure text. (7) **Re-wording is in scope:** each affected card's existing text may be re-worded where needed to carry the restored rules in that card's own voice and structure (numbered-rule placement, existing sentence integration, reference cross-wiring) — the SCs bind the semantic elements each card must state, not the literal wording; re-wording must not alter the cards' other semantics, and any sentence whose meaning changes beyond this item's scope stays untouched. |
| 6 | **User Intent / Original Prompt** | "approved for spec audit: .opencode#2551" → audit attempt → developer: "bullshit"; "fabricated fails"; "so a bunch of fabricated fail reasons to not setup the spec properly locally for an audit. this is a regression. file a fix spec after auditing the attic" |

## 2. Not Included

- **The attic DiMo dispatch topology** — single-fresh-context-reviewer stays (Alternative (a)).
- **The full attic BLOCKED-state matrix for spec creation** — the creation path already constructs the local record; only the repair path is restored (Alternative (b)).
- **A retroactive mirror sweep over historical issues** — forwards-only on discovery (Alternative (c)).
- **Changes to the `spec` card's verdict semantics or `validation-standards.md`** — #2575 governs that surface; the verdict semantics are not this item's defect. Re-wording inside the four affected cards is in scope (Design Decision 7) but bounded: it carries the restored rules in each card's voice without altering the cards' other semantics.
- **Changes to `floor.md` or `routing.md`** — routing already lands issue operations on the `issues` card and audits on the `verify` card; no routing entry is needed.
- **Remediation of `.opencode#2551` itself** (mirroring its artifacts, running its audit) — that is the observed failure's own remediation, executed under the restored rules once this spec is implemented; it is not part of this change's deliverables.
