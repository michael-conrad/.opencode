# [REGRESSION] Audit criteria substance lost in the #2490 re-rip

## 1. Intent and Executive Summary

| # | Field | Description |
|---|-------|-------------|
| 1 | **Problem Statement** | The deck's audit surface regressed into a hollow form in the #2490 re-rip: the audit vocabulary survived — the floor's `audit` / `remediate [and re-audit]` utterances, the verify card's fixed-criteria-set requirement — but the criteria that vocabulary points at did not. Observed 2026-10-13 by auditing the pre-rip deck (preserved under `attic/`, tag `pre-rip`) against the live deck. Five facets: (1) plans are never audited — no plan-side criteria set exists anywhere in the deck and the plan card has no validation dispatch, so a plan reaches `implement` unchecked; (2) implementation audits lost the test-quality families (edge-case completeness, cross-boundary coverage, assertion-weakening detection, RED evidence, sequential RED→GREEN per item) and the reverse drift direction (implementation beyond the spec, spec-required surfaces missing, signature mismatch); (3) the spec validation criteria set (7 defect classes, `spec/references/validation-standards.md`) covers only the SC-table layer of what the pre-rip spec-audit checked — the 11 holistic dimensions, the nine analysis families, and the six decomposition criteria restored by #2116 are all absent; (4) the evidence-type rule survives only as two named examples instead of the instrument-capability principle — an instrument that cannot in principle detect the criterion's failure mode produces no evidence; (5) `routing.md` has no row matching an on-demand audit of an existing artifact, though the floor vocabulary names `audit` and `remediate [and re-audit]`. |
| 2 | **Root Cause / Motivation** | The #2490 rip-and-replace retired the pre-rip `audit` card wholesale — roughly 17,000 lines across twelve audit types, each a 4-role Investigator → Validator → Evaluator → Arbiter chain (sources under `attic/skills/audit/tasks/`) — together with the plan-fidelity criteria (`attic/skills/audit/tasks/plan-fidelity-evaluator.md`), the test-quality criteria (`attic/skills/audit/tasks/test-quality-audit-evaluator.md`), the drift-detection criteria (`attic/skills/audit/tasks/drift-detection-evaluator.md`), the holistic dimension definitions (`attic/reference/holistic-dimensions.yaml`), and the decomposition criteria (`attic/audit-reference/reference/decomposition-criteria.md`). Subsequent restorations rebuilt pieces around the gap — #2550 the single-reviewer verdict semantics, #2557 the release gate, #2597 the artifact-presence gate — but no restoration rebuilt the criteria sets themselves, leaving the deck's audit dispatch language pointing at a criteria base that no longer exists. |
| 3 | **Approach Chosen** | Restore criteria depth, not audit machinery, per the developer's 2026-10-13 direction (determine the card set; customize text per card; least ceremony, no floor growth). Six surfaces: (1) `spec/references/validation-standards.md` — defect classes expanded to carry the restored analysis families, each judgment-phrased for reviewer judgment with no keyword lists: bidirectional traceability (orphan SCs and untested root causes are both findings), fabricated claims (asserted without source evidence; negation claims without exhaustive verification behind them), internal contradiction (explicit, implicit, scope), escape hatches (language licensing the implementer to short-circuit the requirements), feasibility (references to non-existent files, functions, libraries, or capabilities), gap analysis (implicit preconditions, untested boundary conditions), scope narrowness (symptom-only fix, over-scoping, systemic implication left unaddressed), research adequacy (alternatives not ruled out; code-state claims without recency verification), decomposition (atomicity, single deliverable, PR-gate viability, ceremony, covered-by-prior), and defect class 5 sharpened to the general instrument-capability form (existence cannot verify content, pattern-match cannot verify meaning, reading cannot verify runtime effect — the instrument must be able to detect the criterion's failure). (2) `plan` — a new plan-side criteria reference (`plan/references/plan-validation-standards.md`) re-authoring the plan-side families for the per-SC item format (item coverage in both directions, explicit acyclic ordering, instrument reality, scope discipline, safety, plus the shared families), self-contained with its own verdict contract and revise→re-validate loop; the plan card gains a fresh-context validation dispatch step executed before `implement` consumes the plan on the full path. (3) `implement` — the test-quality families integrated with the existing test-value gate (edge cases and error conditions relevant to the item's behavior, cross-boundary assertion reality where the change crosses module boundaries, no assertion weakening without the asserted behavior changing, each RED confirmed failing before its GREEN, sequential per-item cycles rather than batch RED then batch GREEN), and the SC-fidelity rule extended with the reverse drift direction (no deliverable the spec or plan does not state; no spec-required surface left missing; drift in either direction is reported, never silently absorbed). (4) `verify` — the instrument-capability rule stated as a general reviewer rule with the behavioral-provenance step as an instance of it, and the criteria-set ownership mechanism: the audited artifact's producing card owns that artifact's audit criteria reference and the audit reviewer reads it — composing with, not replacing, the existing criteria-invariance rule. (5) `routing.md` — one row routing an on-demand audit of an existing artifact to the verify card with the artifact's criteria set. (6) Ledger entry in #2534 (attic sources, #2490 retirement, observed failure, placements, declined candidates). |
| 4 | **Alternatives Considered & Why Discarded** | (a) Restoring the 4-type evidence taxonomy (behavioral / semantic / string / structural) from `attic/reference/cost-model-standards.md` — discarded: the four types are enumerated instances of one instrument-capability principle, which restores in a single judgment-phrased defect class; the types were load-bearing only as inputs to the retired DDL cost model (1×–1000× multipliers, death-spiral numerology); and the binary is deck-normal across the spec card and routing descriptions, so a taxonomy change is cross-cutting churn. (b) Restoring the 4-role DiMo dispatch chains — discarded: the single-fresh-context-reviewer shape is the #2550 restoration's deliberate design; criteria depth is the lost substance, not the dispatch topology. (c) Restoring `verdict.yaml` / `evidence.yaml` artifact chains — discarded: banned by the skill-creator card's standards ("no artifact chains"); verdicts remain single records in chat or the PR description. (d) Restoring the lexical self-consistency gate (hedging-keyword scans downgrading PASS verdicts) — discarded: keyword scanning over judgment is the deck's founding defect class; the verdict contract already carries the intent in judgment form ("a PASS with any disclosed observation is not a verdict"). (e) Restoring a dedicated `audit` card — discarded: audits route through the verify card per the floor vocabulary; a second audit surface re-creates the routing ambiguity the re-rip resolved, and audit criteria belong with the producing cards whose artifacts they judge. (f) Restoring the fixed 7-analytical-artifacts mandate (blast radius, concern map, code-path inventory, cross-cutting matrix, interface compatibility, state analysis, testability assessment) as an audit entry gate — discarded: the explore card already produces analytical artifacts when the change touches those surfaces; a fixed mandatory set is TDT-era ceremony. (g) Restoring closure-verification depth, PR-body template audit, and deck-content audit criteria in the same change — deferred: each has partial live coverage (the verified-resolved closure path #2561, inline PR-body requirements, governance gates plus the reference-integrity tool), none carries its own observed failure, and bundling them grows the ceremony surface without demand; recorded as declined candidates in the ledger entry. |
| 5 | **Key Design Decisions** | (1) The behavioral/structural classification stays binary — the design question the developer ratified on 2026-10-13 (least ceremony, no fat always-injected surface); the instrument-capability principle replaces the taxonomy, and `floor.md` gains nothing. (2) Criteria sets live one level deep in the producing card's `references/` and are owned by that card; the verify reviewer consumes the owning card's reference — criteria depth without always-injected surface. (3) Every restored criterion is judgment-described (intent-decidable; scripts forbidden) — no keyword lists, no trigger-word tables, no numeric verdict thresholds; the defect classes describe failures a reviewer recognizes, in the same register as the existing standards reference. (4) The plan validation dispatch mirrors the spec card's step-6 shape and is scoped to the full path — short-path changes produce no plan and run no dispatch. (5) Test-quality content integrates into implement's existing test-value gate and workflow chain rather than a parallel section — one home per rule, no drift between duplicated statements. (6) Re-wording is in scope: each affected card's existing text may be re-worded to carry the restored rules in that card's own voice; the SCs bind the semantic elements each card must state, not literal wording; re-wording must not alter the cards' other semantics. (7) The attic is source material only — restoration is re-authoring per the developer's customization directive; the ledger entry names the source paths so future audits can verify the derivation. |

### Cost Frame

Criteria-depth restoration across four cards, one new reference, one routing row, and one ledger entry — the smallest surface that gives the deck's audit dispatch language its criteria base back. Growth lands entirely in load-on-demand references (the `validation-standards.md` expansion and the new `plan-validation-standards.md`); the four card bodies grow by a few lines each; `routing.md` grows by one row; `floor.md` grows by nothing (SC-9). No behavioral SCs: the criteria are intent-decidable instruments applied by reviewer judgment, and scripting agent behavior against them would re-create the deck's founding defect; the dispatch machinery that applies the criteria (the validation dispatches and the verify reviewer) already exists and runs on every full-path cycle. The structural SCs make the restored text falsifiable; every future audit applies the criteria by judgment.
