# [SPEC] retire the routing.md dispatch table — skill card descriptions become the sole routing surface, gated by a coverage audit

## 1. Intent and Executive Summary

| # | Field | Description |
|---|-------|-------------|
| 1 | **Problem Statement** | `.opencode/routing.md` (45 lines: 27 dispatch rows plus a card-origins footer, 527 words) is an always-injected manual dispatch table — listed in `opencode.jsonc`'s `instructions` array and re-ordered read by `prompts/default.txt` — that duplicates the dispatch trigger surface the platform already presents through the skill cards' frontmatter descriptions. 26 of the 27 rows' primary payloads restate a card description's load-when clause — three as character-exact substrings (`spec`, `plan`, `multimodal-dispatch`), the remainder as close paraphrases; the deck's own governance card declares *"Descriptions are the router"* (`skill-creator` §Card standards). The duplicate surface is a standing drift hazard with drift already demonstrated inside the table: it references a **vendor hf card that does not exist in the deck** (35 cards; none is hf), maps **"notebooks" to "the matching connector card" when no notebook connector card exists** (notebook dispatch is carried by floor's external-access table), and hand-waves *"the matching release-trio card"* without naming cards. Every description revision creates a second manual update point. The cost is ~527 words injected into every session on two surfaces, buying no dispatch capability the descriptions do not already provide. The developer ruled (2026-10-15): routing is supposed to be handled by skill card descriptions, not by a manual dispatch table, and *"the table is a danger."* |
| 2 | **Root Cause / Motivation** | The table entered the deck in the #2490 re-rip (provenance line: *AI-authored, .opencode#2490*) as part of the replacement deck's always-injected tier, alongside the card descriptions it mirrors; `skill-creator`'s card standards subsequently codified descriptions as the router, but the table survived as a parallel copy of the same dispatch surface. Because a second copy of a dispatch mapping has no update path that reaches it automatically, it drifts — and has drifted: the hf-card reference and the notebooks mapping name surfaces that do not exist in the live deck (both verified absent from `skills/` on 2026-10-15), and the release-trio row names no cards at all. The reverse direction proves the mechanism is complete without the table: `java`, `python`, `gradle`, and `godot` carry descriptions and **no routing row**, and dispatch description-only today. The developer's ruling resolves the open design question this analysis raised (whether the table served as a deliberate human-legibility index): it is a danger, not an asset — removal, not demotion. |
| 3 | **Approach Chosen** | One coherent change set, audit-first ordered: **(1)** a fresh coverage audit re-derives, against the live deck, the dispatch-surface map for every row of the pre-removal table — the 27 rows plus the card-origins footer enumerated in §2 below, which is the audit's fixed criteria set — and remediates any description found to under-trigger its row's intent (remediation candidates identified by the preliminary analysis: the on-demand-audit row's trigger is floor-carried, not stated in `verify`'s description; the wiki row's "wiki submodule conversion" element is absent from `wiki-operations`'s description trigger list; the hf row is a dead reference with nothing owed; the notebooks element is floor-carried). **(2)** `routing.md` is deleted. **(3)** Every live reference is conformed: `opencode.jsonc` (instructions array), `prompts/default.txt` (read directive), `floor.md` (the description-matching directive at the loading-on-demand paragraph and the deck-governance line's "or the routing index" clause), `.opencode/AGENTS.md` (pointer text), parent-repo `AGENTS.md` (pointer text and the reference-files table row), and `skill-creator` (frontmatter description's file list; the admission gate's *"a routing entry"* mechanism vocabulary, which names a surface that no longer exists). **(4)** The retirement decision is recorded in the deck-debt ledger (#2534). **(5)** The deck's retrieval index is refreshed: ragsync's `opencode-deck` source (`ragsync-config.yaml`, watch enabled) indexes the submodule's markdown including `routing.md`, so the `opencode_deck` collection is a live dependent — post-change it must carry no chunks derived from the removed file. **(6)** Token-count evidence per the developer's direction (2026-10-15): a tests-v2 harness session driven by a hello-style trivial prompt is executed against the pre-change deck commit and again against the post-change deck commit under identical conditions — same scenario script, same model (`DEFAULT_TEST_MODEL`), same prompt — exporting each session's prompt-token accounting; the pair demonstrates the injected-surface reduction at runtime rather than by word count. The parent-repo `AGENTS.md` conformance and the submodule pointer bump ride in the same parent commit (pointer-only commits are prohibited). The removal's PR gate opens only with the audit at zero uncovered rows. All deck edits go through the skill-creator admission gate; this item is developer-directed (carve-out applies; the gate's content standards bind). The card-origins taxonomy needs no relocation: `skill-creator` §Vendor-card boundary already carries it verbatim (*"Card origins: deck-authored (governed) / vendor-generated / project-local"*). |
| 4 | **Alternatives Considered & Why Discarded** | (a) **Demote the table out of the injection surface but keep it as a human-legibility index** — discarded: the developer ruled the table is a danger; any retained copy preserves the two-sources-of-truth drift hazard the three demonstrated drift defects exemplify, and every description revision still owes the copy a manual sync. (b) **Behavioral dispatch tests instead of the static audit** (harness runs asserting an agent loads the right card for a phrased intent) — discarded: they would exercise the platform's description-matching mechanism, not this change's surfaces; the mechanism is unchanged by this item and already proven by the four description-only cards; 27+ expensive harness runs buy marginal signal over an audit that reviews the same trigger surface the mechanism consumes. (c) **Replace the file with a pointer stub** ("see the descriptions") — discarded: the developer directed clean removal; a stub keeps a dead file in the injection list and a touchpoint in `opencode.jsonc` and `prompts/default.txt`. (d) **Relocate the card-origins taxonomy into `floor.md`** — discarded: `skill-creator` §Vendor-card boundary already carries the taxonomy verbatim; a floor copy would re-create exactly the duplication this change removes. (e) **Fix only the three drift defects and keep the table** — discarded: symptomatic repair; the root cause is the duplicate surface itself, and the next description revision re-opens the drift window. |
| 5 | **Key Design Decisions** | (1) **Audit-first ordering inside one change set:** audit → remediate → delete → conform → ledger; the coverage-audit artifact exists in the issue folder before the removal's PR is opened — a removal without a zero-finding audit verdict is incomplete work, not a partial PR (git-workflow-pr's completed-work bar). (2) **The audit's criteria set is fixed by this spec:** §2 enumerates all 27 rows plus the footer with their preliminary destinations; the audit cannot silently narrow scope — audits run on a fixed criteria set. (3) **The coverage judgment is intent-decidable** — executed by fresh-context review, never a script; scripts verify only mechanical facts (file absence, reference grep). This follows the deck's founding-defect rule: static checks on intent are prohibited. (4) **The developer's "double-check" is realized as fresh-context re-derivation** (SC-4): a second, independent pass over the live descriptions against the enumerated rows — not a re-read of this spec's preliminary map; disagreement between the fresh derivation and the recorded map is a finding. (5) **Description remediations go through skill-creator governance** (developer-directed carve-out applies; the content standards bind — descriptions stay deliberately pushy, state both abstraction levels, and never match user phrases). (6) **No replacement index of any shape** — no new routing file, no condensed table, no summary row set; the descriptions and the floor's existing content are the entire post-removal dispatch surface. (7) **Parent-repo coherence:** the parent `AGENTS.md` conformance and the submodule pointer ride one commit. (8) **Re-wording is in scope** per the #2597 doctrine: the SCs bind the semantic elements each surface must state or must not state; any sentence whose meaning is unchanged by the table's removal stays untouched. (9) **The hello-probe runs are measurement vehicles, not behavioral assertions about the agent** — the tests-v2 real-domain-task rule governs prompts whose SCs assert agent task behavior; SC-8/SC-9's criterion judges the session's prompt-token accounting, so the developer-directed trivial prompt is the probe itself, run twice under identical conditions with the deck commit as the only differing input. (10) **The token comparison is directional, not numeric-promissory**: the criterion binds after < before with both counts recorded — the spec promises no specific delta, because tokenizer and platform accounting variance is not this change's subject. |
| 6 | **User Intent / Original Prompt** | "routing is supposed to be handled by skill card descriptions, not by a manual dispatch table. analyze .opencode with this in mind and report." → analysis reported (2026-10-15): 27-row table, 26 rows description-duplicated, three drift defects, four description-only cards, blast radius enumerated → developer: "the table is a danger. create a spec to cleanly remove it and to double-check the descriptions on the skill cards so that unexpected lobotomization doesn't occur." → mid-validation addition (2026-10-15): "I would also like before and after token counts with a 'hello' style prompt." |

## 3. Not Included

- **Description-quality work beyond the table's dispatch surface** — the audit's scope is the 27 enumerated rows plus the footer; general description improvements outside that payload are deck-governance business, not this item.
- **The floor's hf external-access line** — it describes the vendor-card boundary generically ("card is vendor-generated via `hf skills add`"); the hf card's absence is not a defect of this change and the line is untouched.
- **CHANGELOG history** — historical entries mentioning `routing.md` (#2587, #2504, and others) are records, not live references; they stay.
- **`attic/`** — the preserved pre-replacement deck is unloaded and excluded from both conformance and the reference grep.
- **Scripted coverage matching** — no keyword/phrase-matching script decides row→description coverage (Design Decision 3).
- **Behavioral dispatch SCs** (asserting an agent loads the right card for a phrased intent) — Alternative (b); the token-measurement pair (SC-8/SC-9) is a different instrument, added on developer direction, and asserts no agent-task behavior.
- **Any replacement index** — no new routing file, stub, or condensed table in any form (Design Decision 6).
- **`prompts/default.txt` content beyond the routing.md clause** and **`floor.md` content beyond the two conformance points** — the surrounding text is unaffected.
- **The `.opencode` submodule's release/changelog mechanics for this change** — the deck CHANGELOG entry, if repo convention requires one, is implementation detail owned by the plan, not a success criterion.

### Cost Frame

One file deletion, six conformance points (nine edit sites: `opencode.jsonc`, `prompts/default.txt`, two in `floor.md`, one in `.opencode/AGENTS.md`, two in the parent `AGENTS.md`, two in `skill-creator`), one coverage-audit artifact, the description remediations the fresh audit independently finds (preliminary candidates: R7, R15's conversion element), one ledger comment, one retrieval-index refresh, one hello-probe run pair with its clean-room evaluation, one parent commit (AGENTS.md + pointer). No new cards, no new references, no replacement index; the always-injected surface *shrinks* by ~527 words per session (the table out, nothing added beyond conformance rewording). Behavioral dispatch SCs are not included (Alternative (b)): the platform's description-matching mechanism is unchanged by this item and already exercised in production by the four description-only cards; the coverage audit reviews the identical trigger surface that mechanism consumes — the same intent-decidable rationale recorded in #2597's and #2606's cost frames. One behavioral measurement pair (SC-8/SC-9: two harness hello-prompt sessions plus one clean-room evaluation) is included on the developer's direction — it converts the ~527-word word-count argument into runtime prompt-token evidence, before and after.
