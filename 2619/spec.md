# Fix Spec — supervision poll discipline regression (.opencode#2619)

## 1. Intent and Executive Summary

| # | Field | Description |
|---|-------|-------------|
| 1 | **Problem Statement** | The agent-supervisor poll discipline keeps regressing despite the behavioral-testing card's mandates and four prior corrections (#2557, #2561, #2570, #2594). Observed again 2026-10-15 during #2617: while supervising a long-running background reindex, the poll interval drifted 60 → 90 → 120 → 150 → 180 → 240 → 270 seconds across consecutive polls, and status reports rode inside tool outputs or were omitted — the developer cannot read tool outputs or agent reasoning, so an unreported interval is invisible time. A developer abort was required to stop an unreported 270-second poll. |
| 2 | **Root Cause / Motivation** | Two gaps compose. (a) **Scope gap:** the 60-second mandate is written as the "Agent-Supervisor Mandate" for behavioral runs (`opencode run` supervision); the supervising agent classified non-model background jobs (a ragsync reindex) as outside the mandate and let the cadence decay "while just waiting." Anything under active supervision by the agent in a working turn is the same discipline problem: the developer is waiting on an invisible process. (b) **Cadence-anchoring gap, scope-relative:** the anchoring the prior corrections wrote is real but scoped with the mandate. #2557's R-15 caps polls at 60 seconds and requires every poll's report ("an unreported poll did not happen"); #2570 hardened the cycle to "absolute — no longer sleeps between polls, ever." Both clauses live inside the Agent-Supervisor Mandate, whose scope is `opencode run` supervision — so for any operation the agent supervises that is not an `opencode run`, none of it applies: no stated ceiling, no stated per-poll update duty. And within the mandate itself, the update's content is defined only in terms of the run agent's state (§9: what the run agent is doing, intends next, whether it serves the goal), leaving the update form for a poll that yields no new evidence on a non-run operation unstated — exactly the poll most likely to tempt omission. |
| 3 | **Approach Chosen** | One card amendment + one lessons-learned record correction. (1) Amend the `behavioral-testing` card's supervise-every-run rule (§9) to bind **any operation under the agent's active supervision in a working turn** — model runs and background jobs alike — to the mandate's fixed 60-second cycle, stating the interval as a ceiling that never escalates while the supervised operation is pending (this extends the cycle's existing "absolute" wording, #2570, from runs to the bound scope rather than establishing it new); and require the substantive in-chat text update after EVERY poll, where "no change" is a valid and required update (the §9 update content is defined only in terms of the run agent's state; the extension states the no-change form). Mirror the same three clauses into `tests-v2/AGENTS.md`'s Agent-Supervisor Mandate section (the mirror site the card already references). Developer-directed item (skill-creator carve-out applies; content standards bind). (2) Correct the 2026-10-15 lessons-learned record. `.opencode/.issues/lessons-learned/session-2026-10-15/` (LL-1) already exists and already records this correction — but its root-cause section states the anchoring gap in a fabricated-negation form ("no prior correction bound the interval itself as a ceiling ... none required the per-poll update when a poll yields no new evidence"), which this spec's corrected diagnosis supersedes; amend that section to the accurate form. (Its Remediation section's "implemented in this change, .opencode#2619" statement becomes true when this change lands; no edit needed there.) |
| 4 | **Alternatives Considered & Why Discarded** | (a) Scripted enforcement (a wrapper that blocks >60s) — discarded: cadence discipline is agent behavior; a script cannot read the chat channel, and the deck's founding-defect rule prohibits static enforcement of intent-decidable behavior. (b) Floor-level rule — discarded: the discipline governs supervised operations, a card-scoped concern; the floor's always-loaded criterion (visible before any card dispatch) is not met — the failure occurs only after a card (behavioral-testing) is loaded and a supervised operation is underway. (c) Lessons-learned entry only — discarded: the entry records the instance; the scope gap that produced it would remain unbound in the governing card. |
| 5 | **Key Design Decisions** | (1) The amendment extends the mandate's existing absolute-cycle rule — the 60-second cycle is already absolute inside behavioral runs (#2570) — to every operation the agent actively supervises: inside the bound scope the interval is a **ceiling**, never escalating while the supervised operation is pending, not a target to stretch. (2) The per-poll in-chat update is **unconditional** — no new evidence still produces the update ("no change" stated plainly) — carried explicitly into the extended scope, where the §9 update-content definition (run-agent state) would otherwise leave the no-evidence poll's update form unstated. (3) The mandate binds **any operation under the agent's active supervision in a working turn**, not only model runs — and with no duration or operation-kind qualifier: the classification boundary that caused this regression is removed, not moved to a new threshold. (4) Card amendment, not new card — the discipline already lives in behavioral-testing; growing a new surface would duplicate it. (5) The chat channel is the only delivery surface — tool outputs and todo lists are insufficient (established #2557). |

## 2. Not Included

- Mechanical enforcement of the cadence (Design Decision: intent-decidable, never scripted).
- Changes to poll-run.sh or harness monitor mechanics — the harness side behaved correctly in the observed instance.
- Retroactive tooling for past sessions — the lessons-learned record is the artifact.
