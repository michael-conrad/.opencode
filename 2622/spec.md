# [SPEC] Deck: restore remote-body format, blockquoted artifacts link, and `{N}/` record-set mandates

Resolves `.opencode#2622` (remediation of `.opencode#2620`).

## 1. Intent and Executive Summary

| # | Field | Description |
|---|-------|-------------|
| 1 | **Problem Statement** | The active deck's `spec` and `issues` cards do not mandate (a) the remote-API issue-body format, (b) the blockquoted artifacts link, or (c) the local `{N}/` record set. An agent following the routed cards verbatim files a thin "## Why / ## What" remote body with a path-style pointer. Two such filings were judged "not a proper remote spec" by the family owner in one session (NewsRxUI#64, ProcessFinishedNotify#36 — GitBucket, 2026-10-15). The only active remote-body rule is the identical weak sentence in both cards: "The remote body is a detailed exec summary (why + final what); the full spec and all artifacts live in `.issues/{N}/`" (`spec/SKILL.md` item 4, `issues/SKILL.md` item 2). The blockquote-URL convention exists in the deck family only as verbiage stranded in `.opencode/.issues/AGENTS.md` (mirrored at `.issues/AGENTS.md`) — a workspace guide, not an operational surface. The full format machinery is preserved-but-unloaded in `attic/skills/issue-operations-core/tasks/{push-artifacts,creation,body-edit}.md` (artifact_url capture, spec-reference blockquote reconciliation, remote-body composition/update flow). |
| 2 | **Root Cause / Motivation** | The #2490 deck rip retired `issue-operations-core` and never translated its three normative mandates — remote-body format, blockquoted artifacts link, local folder requirements — into the replacement cards; the replacement carried a weaker rule instead. Motivation observed 2026-10-15: owner verdicts on the two thin filings, followed by this session's design brainstorm with the developer. |
| 3 | **Approach Chosen** | One shared deck-owned reference at `skills/spec/references/remote-body-format.md` defining, for every remote issue with a matching issues-data `{N}/` folder: the mandatory remote-body section set (Problem; Scope with success criteria classified behavioral/structural each carrying a verification instrument; Out of scope; Requirements as R-x SHALL statements; Approach; Impact; a success-criteria table; plan-shaped sections — Items RED/GREEN, Dependencies, Traceability, Enforcement Gate, Edge Cases, Not Included — once a plan exists), the sizing doctrine (fuller-but-still-exec-summary: self-sufficient for developer judgment without opening the local store; full agent-ingest detail stays local-authoritative), the closing blockquoted artifacts link (`> Full spec and plan artifacts: <url>`, built via `local-issues url --number repo#N --artifacts`, present at filing and reconciled on every remote-body edit), and the `{N}/` record-set requirement (`spec.md` plus the tool-managed `issue.yaml`/`comments.yaml`/`links.yaml` and artifact subdirectories). `spec/SKILL.md` item 4 and `issues/SKILL.md` item 2 replace their body-format sentences with pointers to that reference. `.opencode/.issues/AGENTS.md` is stripped of its operational "GitHub URL Convention" section and exec-summary doctrine phrasing — the convention's normative form moves into the deck reference — leaving layout/tooling description pointing at the reference; `.issues/AGENTS.md` (already a collapsed pointer) has its pointer description updated to cite the deck reference. All card and reference edits go through the skill-creator admission gate. |
| 4 | **Alternatives Considered & Why Discarded** | (a) Restore `attic/skills/issue-operations-core` wholesale — discarded: the attic is preserved-unloaded pending soak/deletion per `.opencode/AGENTS.md`, and the rip deliberately retired its pipeline shape; the fix is translation of three mandates, not resurrection of a retired pipeline. (b) Put the format mandate only in the `spec` card — discarded: `issues` carries the same weak rule and owns remote-first filing for every issue type; two independent rule sites is the drift shape that produced this defect (the identical sentence now lives in two cards). One reference, two pointers, one criteria source. (c) Keep the blockquote convention in the workspace guides and cross-reference it — discarded by developer ruling: workspace documentation is not the operational deck and must not contain operational requirements; the stranded verbiage is misplaced deck content and is relocated. (d) Mandate keyed to issue type (spec-issues only) — discarded by developer ruling: the trigger is possession of a matching issues-data `{N}/` folder, fact-decidable, no type taxonomy to maintain; issues filed first gain the mandate at reconciliation when their folder comes to exist. (e) Full spec mirrored into the remote body — discarded by developer ruling: the remote body stays exec-summary style, self-sufficient for the developer, without the full agent-ingest detail the local spec carries. |
| 5 | **Key Design Decisions** | (1) Single shared reference — one criteria source, mirroring the deck's validation-standards pattern (`spec` and `plan` already share one reference per concern). (2) Sizing rule stated as a testable property: "a developer reading only the remote body can understand and judge the spec; the local spec holds everything an executing agent needs beyond that." (3) Trigger = folder existence, not issue type. (4) The reference may state the manual platform-URL derivation (per repo facts, SSH-to-HTTPS conversion) as the fallback build mechanic while the companion tool spec (`local-issues` ssh:// parsing, `.opencode#2623`) is unlanded — the mandate is not blocked on the tool. (5) Predicate classification: all deck-text criteria are structural (file facts); the end-to-end filing behavior is the single behavioral SC. (6) The workspace-guide strip is content relocation, not deletion — the convention text moves into the reference, guides keep only a pointer. |
| 6 | **User Intent / Original Prompt** | Session 2026-10-15: "triage .opencode#2620 and brainstorm a fix spec" → triage verified both #2620 defects against the live deck; design brainstorm with developer rulings: "item c: .issues/ is not a part of the operational deck, it should not contain operation requirements like this"; "the workspace documentation is misplaced deck verbiage"; "a fuller but still exec summary style remote spec is preferred so that the dev doesn't have to hunt down the full spec for a proper understanding of the spec, the remote spec just doesn't need to the full detail in it that the local spec does that is ingested by the agent"; on spec structure: "I have no clue. You are the one analyzing the requirements for the spec or specs" (two-spec split adopted per analysis); on trigger scope: "it generally should be any issue that has a matching issues-data branch folder"; "proceed" finalized the design. |

## 2. Not Included

- **The `local-issues` URL-builder fix** — ssh:// parsing and per-host browser-base mapping are the companion spec `.opencode#2623`; this change's reference may name the manual derivation as the interim mechanic.
- **Store-primaryity changes** — `.issues/{N}/spec.md` remains the authoritative full spec; the remote body remains a structured summary of it.
- **Attic changes** — `attic/` stays preserved-but-unloaded; no file under `attic/` is edited or restored.
- **Validation-standards or plan-validation-standards changes** — those criteria sets are separate deck-governance surfaces; this change does not touch them.
- **Retroactive remediation of the two judged filings** (NewsRxUI#64, ProcessFinishedNotify#36) — the mandate binds future filings; those records stay as evidence.
- **Card description rewrites** — routing descriptions stay untouched; only the body-format rules inside the cards change.
