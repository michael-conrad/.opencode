# [SPEC] Closing-keyword contract — form-selection rule, platform class, and merge-vs-close distinction

Resolves `.opencode#2658`.

## 1. Intent and Executive Summary

| # | Field | Description |
|---|-------|-------------|
| 1 | **Problem Statement** | The deck's closing-keyword contract is incomplete and partly false, in three ways. (a) **No form-selection rule.** `git-workflow-pr` §4 states the forms (`Closes #N`, `Closes owner/repo#N`, `Refs #N`) and two prohibitions (a `#N` carrying no closing keyword, and the owner-less qualified `repo#N`), and never states the rule that chooses between them — whether the referenced issue lives in the pull request's own repository. (b) **A platform class the model cannot express.** The same card says closing keywords *"auto-close the remote issue at default-branch merge on platforms that support it: GitHub confirmed for both forms; **GitBucket has no closing-keyword auto-close** — cleanup performs closure there."* That clause is false — measured, GitBucket closes the same-repo form on a default-branch merge — and a binary per-platform class cannot express GitBucket's actual behaviour, which is per *form*: the same-repo form closes, the cross-repo form does not. The prohibition also collides with the form that works: the banned owner-less `repo#N` is a suffix of the owner-qualified `owner/repo#N` that does close. (c) **A closed pull request is not a merged one.** `git-workflow-cleanup` item 1 verifies *"the merge"* without saying what distinguishes the two, and `gb-cli` documents two ways to *close* a pull request and never mentions that the merge is a human gate. |
| 2 | **Root Cause / Motivation** | (a) The #2615 work record's empirical step was executed and its outcome recorded, but the record names no command and its recorded outcome does not discriminate between a close and a merge into a non-default branch — so it establishes no platform fact, and the platform fact was written into card prose regardless. The clause is therefore **measured false**, not merely unverified (research artifact §1). (b) The same installation put forms and prohibitions into the card but no selection rule, and banned a form by a name that is a suffix of the form that works. (c) No card states the distinction, so nothing in the deck tells an agent that a close is not a merge. |
| 3 | **Approach Chosen** | Replace three statements in three cards. `git-workflow-pr` §4: state the form-selection rule; state the class per (platform × form); reword the prohibition so it bans the owner-less qualified form and preserves the owner-qualified one; state that the developer's merge is what fires the close. `git-workflow-cleanup` item 1: distinguish a closed pull request from a merged one. Item 3: name the cases the keywords leave open and their precedence, retain the general closure fallback in substance, and replace the three vestigial per-platform class phrases with a pointer to `git-workflow-pr` §4. `gb-cli` §4: state the human merge gate, that `PATCH .../pulls/{n}` with `state: closed` closes without merging and produces no closing-keyword closure, and that GitBucket's issue API reports `state` but not `closed_at`. No new gate, no new workflow, no new test, no change to GitBucket. |
| 4 | **Alternatives Considered & Why Discarded** | (a) A "discriminating probe" discipline clause on the operational cards — discarded by the developer: the rule is process content and belongs in the process layer; the operational cards load on every PR and every GitBucket contact, and the paragraph would be actionable by none of them there. The rule already exists in the process layer (`verify` §11 instrument capability; `plan-validation-standards` #12; `spec/references/validation-standards` #5), and a prose rule would not have caught the #2615 failure — the record's recorded *outcome* was non-discriminating, so no rule about how to phrase a record repairs that. (b) A post-implementation gate in `implement` — same objection, and inert at that hook: the false statement was written into card prose before implementation began. (c) A `tests-v2` scenario that merges for real — discarded by the developer as a new workflow rather than a correction. (d) A generic "depends on the platform" hedge — discarded: the platform fact is knowable and measured, and a hedge reproduces the vagueness that produced the defect. (e) Leaving `gb-cli` untouched — rejected: the card documents two ways to *close* a pull request and never mentions that the merge is a human gate, nor that a close is not a merge; that omission is what left a closed and a merged pull request indistinguishable. (f) Restoring the pre-rip `attic/skills/git-workflow-pr/reference/closing-keywords.md` — discarded: retired, GitHub-centric, and it introduces the `Implements` keyword the uniform-`Closes` contract rejected. |
| 5 | **Key Design Decisions** | (1) **Correct the text; do not add a mechanism.** Sentence replacements, plus the two provenance surfaces each edited card carries by the deck's uniform practice. (2) **The class is per (platform × form), not per platform** — GitBucket is in the keyword-closure class for the same-repo form and outside it for the cross-repo form, and a binary per-platform class cannot express that. (3) **State the decision rule, not just the forms.** (4) **The prohibition must distinguish owner-less from owner-qualified.** (5) **The merge is the developer's** — the floor's human-merge gate makes the merge a human action, so the closing lines are what make that merge close the ticket, and the agent's duty at cleanup is to verify and sync. (6) **Closed is not merged.** (7) **No merge command enters the deck.** (8) **The change must not narrow any pre-existing duty** — the cleanup card's general closure fallback is retained in substance, and the new remit statement is scoped to closure, leaving the workflow's other duties unqualified by branch. (9) **Predicate classification** — every criterion is fact-decidable: a card read, a grep, or a diff. (10) **Root-agnostic** — the corrected text names forms and platforms only. |
| 6 | **User Intent / Original Prompt** | Session 2026-10-23: the developer reported that *the deck misleads the agent into concluding that GitBucket does not accept standard GitHub close markers in PRs*, that *this is erroneous*, and asked for a fix spec; then that *the agent is not formatting the PR bodies correctly to autoclose the issue tickets that need closing because it thinks the keyword closing won't work*; that the change is *correcting the false premise and any incorrect wording in any of the skill cards and deck docs*; that *not implementing a new workflow*; and that *the agent is not allowed to merge PRs*. |

### 2.2 Surfaces deliberately untouched

- **Reference documents** — none. `git-workflow-pr`, `git-workflow-cleanup`, and `gb-cli` are single-`SKILL.md` cards with no `references/` directory; there is no level two to push detail into, and creating one for a paragraph would be net-negative (new file, new load).
- **The issue store's own records** — the #2615 work record and the prior research card are corrected by `.opencode#2659`, separately. They are separated because they land on a different repository surface (the store's `issues-data` branch, not the deck's trunk) and because a record's factual accuracy is a different concern from normative card prose.
- **`skills/issues/`** — its closure content (§5 Closure, §6 ticket-state hygiene) governs *when* closure is authorized and local↔remote reconciliation, not platform closing-keyword mechanics. Those mechanics live where this change puts them: `git-workflow-pr` §4 and `git-workflow-cleanup` item 3. `gb-cli` §5 carries only the non-interactive issue-state-change route (`?action=close`), not the closing-keyword semantics.
- **`skills/release-promoter/`, `skills/changelog-generator/`** — no platform-class claims.
- **`skills/gh-cli/`** — its `gh pr create/edit/view/merge` line is a capability listing, not an instruction; no card instructs the agent to merge.
- **`floor.md`, `guidelines/`, `AGENTS.md`, `README.md`, `CHANGELOG.md`** — swept; none asserts a GitBucket closing-keyword fact.

### 2.3 Impact

Consumers: every agent that opens a pull request (the `git-workflow-pr` card loads on the PR boundary) and every agent that runs post-merge cleanup (the `git-workflow-cleanup` card).

The live cost of the current text is prospective and established by measurement, not by history. The false platform clause tells an agent that the keyword does not close, so an agent working on a GitBucket-hosted repository issues a redundant close against a ticket the merge already closed — and `gb issue close` falls back to the web UI and **hard-fails** in any non-interactive context (exit 1, "not a terminal"), so the agent spends a failing action on a closed ticket and may read that failure as a closure problem rather than as the redundant action it is. The absent form-selection rule leaves an agent to infer which form applies; the absent merge/close distinction leaves a closed pull request readable as a merged one.

The historical record shows what the *absence* of any keyword guidance cost: in the nine observed instances, no merge closed its target, and the tickets' closure came from elsewhere. Those instances predate the current card text (research artifact §3), so they evidence the cost of the earlier absence, not the current wording's — this spec makes no claim that the current wording has been observed producing a wrong form. The current wording's defects are the readable ones in §6.

Blast radius: three cards, no code, no test surface, no behavior change to any tool.

## 3. Requirements

- **R-1** — `git-workflow-pr` §4 SHALL state the form-selection rule: the form follows whether the referenced issue lives in the pull request's own repository — same repository `Closes #N`; a different repository `Closes owner/repo#N`, always owner-qualified.
- **R-2** — `git-workflow-pr` §4 SHALL state that closing keywords close the referenced issue when the pull request is merged into the repository's default branch, and SHALL name which platform/form combinations close: GitHub for the same-repo and the cross-repo form, GitBucket for the same-repo form only.
- **R-3** — `git-workflow-pr` §4 SHALL prohibit a `#N` reference carrying no closing keyword and the owner-less qualified form `repo#N`, and SHALL state that the owner-qualified form `owner/repo#N` is a distinct form that closes on GitHub, while pointing at the cases a cross-repo reference cannot close by keyword. That pointer SHALL use the deck's canonical agent-facing cross-reference form, `Read [Text](path)` with a deck-relative path, and SHALL be written so that `.opencode/tools/reference-integrity` resolves it — `Read [the git-workflow-cleanup card](../git-workflow-cleanup/SKILL.md)` — and not as a bare `§N` or a bare file name. The bare-`§N` exclusion is enforced by the tool, which matches a link's text against the target file's headings and reports a link whose text names no heading in the target as broken; the bare-file-name exclusion is the `skill-creator` card's normative cross-reference rule, which the tool does not enforce (a file-level link passes the tool vacuously), so the criterion asserts the form directly.
- **R-4** — `git-workflow-pr` §4 SHALL state that the developer's merge is what fires the close, consistent with the human merge gate.
- **R-5** — `git-workflow-cleanup` item 1 SHALL distinguish a closed pull request from a merged one, requiring the merge state to be read rather than the pull request's open/closed flag.
- **R-6** — `git-workflow-cleanup` item 3 SHALL name the two cases the closing keywords leave open, using terms that do not overlap — the cross-repo **form** `owner/repo#N` on GitBucket, where no cross-repo form closes, and a merge into a **non-default base branch**, where the keyword cannot fire at all — and SHALL state the precedence: the base-branch condition governs first, so when the merge did not land on the default branch the ticket's closure is outside the workflow's remit because the work has not landed there, and the cross-repo form on GitBucket is closed by the workflow when the merge did land on the default branch. The remit statement SHALL be scoped to **closure only** and SHALL NOT narrow the workflow's other duties (merge verification, branch deletion, trunk sync, work-state removal), which remain unqualified by branch. Item 3 SHALL **retain in substance the general fallback it currently carries** — that where the closing keywords do not close the issue, closure happens in the cleanup workflow or on explicit developer instruction — with the two named cases as its confirmed instances, so that the pre-change duty is preserved and not narrowed to an enumeration. It SHALL retain the rule that an issue the keywords already closed is not closed again.
- **R-7** — `gb-cli` §4 SHALL state that the merge is a human gate, that `PATCH .../pulls/{n}` with `state: closed` closes without merging and produces no closing-keyword closure, and that GitBucket's issue API reports `state` but not `closed_at`.
- **R-8** — The change SHALL introduce no instruction to merge a pull request, and the deck's existing human-merge-gate statements — `git-workflow-pr` §6 and `floor.md`'s `## Pipeline` section — SHALL remain in force and unmodified.
- **R-9** — `git-workflow-cleanup` item 3 SHALL replace its whole vestigial binary-class wording — all three per-platform class phrases it currently carries: "on platforms that support it", "on platforms without closing-keyword support", and the parenthetical naming which platforms fall in which class — with a pointer to the per-(platform × form) statement in `git-workflow-pr` §4, since the change removes the binary class that wording describes. The replacement of the general fallback clause is governed by R-6, which requires it to be retained in substance.
- **R-10** — Each edited card SHALL carry the `.opencode#2658` anchor in its frontmatter `provenance:` line and in its `<!-- Provenance: … -->` comment, matching the deck's uniform practice on card edits.

## 6. Evidence and its location

The measurement and the historical record live in a research artifact, not in this spec: [the closing-keyword measurement](research/closing-keyword-measurement.md) — the GitBucket 4.48.0 behaviour matrix, the upstream source reading, the observed instances in the family repositories with their dating, the `gb` CLI probe results, and the reconciliation with the prior research card. This spec cites it; it does not restate it.

Two facts from it carry the requirements:

- **The platform class (artifact §1).** Measured on GitBucket 4.48.0 in the tests-v2 self-contained container: the same-repo `Closes #N` **does** close the issue when the pull request is merged into the repository's default branch, and the cross-repo `Closes owner/repo#N` closes nothing. The upstream parser requires whitespace immediately before `#`, so a qualified reference yields no issue id at all and the close lookup is never reached. The card's clause "GitBucket has no closing-keyword auto-close" is therefore false, and a binary per-platform class cannot express GitBucket's per-form behaviour.
- **The #2615 record establishes no platform fact (artifact §2).** It names no command, and its recorded outcome — HTTP 200 with the issue still open — is produced both by a close and by a merge into a non-default branch, so the recorded outcome does not discriminate.

The basis for the three card defects is the cards themselves, quoted here so the spec stands alone:

| Defect | The current text |
|---|---|
| No form-selection rule | `git-workflow-pr` §4 states the forms and the prohibitions and never states that the form follows whether the referenced issue lives in the pull request's own repository. |
| The false platform class and the colliding prohibition | `git-workflow-pr` §4: *"Closing keywords auto-close the remote issue at default-branch merge on platforms that support it: GitHub confirmed for both forms; **GitBucket has no closing-keyword auto-close** — cleanup performs closure there."* and *"Prohibited: a bare `#N` with no keyword, and the deck-qualified `repo#N` form in a closing-keyword position — neither closes anything."* — the banned owner-less `repo#N` is a suffix of the owner-qualified `owner/repo#N` that does close. |
| Closed is not merged | `git-workflow-cleanup` item 1: *"**Verify the merge** via the platform API (`gh`/`gb`) — never assume from memory or cache; the API call is the evidence."* — the card nowhere says what distinguishes a closed pull request from a merged one. |

**On the observed instances.** The artifact's historical instances show what the *absence* of keyword guidance produced. All nine predate the current card text, which entered the deck at commit `7df0f45c` (2026-10-15T03:29:47Z) — the latest instance merged fifty-three minutes earlier. They are therefore **not** evidence that the current wording produces a wrong form, and this spec makes no such claim: the current wording's defects are established by the card quotes above, and the developer's reported symptom is the stated requirement. What the instances establish is the cost of leaving the rule unstated.
