## Candidate remedies — weighed (the report delegates weighing to triage)

- **Candidate 1 — record the provenance + scope statement in the cycle's issue
  record (issue store, `issues-data` branch).** Sound. The store is the deck's
  own sanctioned agent-owned workspace (floor's issues-data exception; the
  store guide: metadata-only orphan branch, never appears in status, not a
  submodule). The record's content class — provenance and a scope statement —
  is issue-tracking metadata, exactly what the store holds. No working-tree
  write, no `.git/` write, owner-inspectable on a named branch, and the deck's
  work cycles already operate against issue records. The store's own
  lifecycle (not a file-deletion step) governs the artifacts.
- **Candidate 2 — configured ephemeral working-tree path (`./tmp/`, gitignored).**
  Rejected. Trades an invisible intrusion for a visible one — still
  agent-authored files in a consuming repo's working tree; the current
  design's "needs no ignore-rule entry" property is lost, so the remedy
  introduces either status noise or an unauthorized repo modification (an
  ignore-rule edit) — the same intrusion class the report flags.
- **Candidate 3 — scope the record requirement down (spec-stage-only cycles
  produce no repository-side file).** Insufficient alone. It addresses the
  observed instance but not the ground: the developer's statement rejects the
  mechanism's file creation and use outright, and implementation-bearing
  cycles would still write into `.git/`.

**Weighed direction:** candidate 1, with candidate 3's reduction applied where
no issue record exists — no repository-side record file in that case (the
PR-preparation surface and git's own evidence serve the provenance consumer;
the existing "never create an issue, or initialize an issue store, to satisfy
provenance" boundary is preserved).
