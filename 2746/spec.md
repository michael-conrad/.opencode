# Spec: .opencode#2746 — Playwright browser-session defaults: msedge + durable saved profile; research skill browser-first over curl

## 1. Intent and Executive Summary

- **Problem Statement.** Agent web research loses to anti-bot surfaces and can never reuse logins under the current deck's browser-session posture. Verified 2026-11-16 during the Cherokee-morphology thesis availability research: bare `playwright-cli open` dies (`Chrome distribution 'chrome' is not found at /opt/google/chrome/chrome`); headless chromium with a throwaway in-memory profile is blocked at WorldCat (Cloudflare HTTP 429), HathiTrust (Cloudflare 403 "Just a moment"), and JSTOR ("Client Challenge" — never cleared across 10s waits and reloads); deep-link search URLs reproduce the walls even after a headed warm-up with the *right* build. A headed chromium with a persistent profile clears the same walls. The developer-correct browser stack observed working 2026-11-16: **Microsoft Edge channel (`msedge`) + the durable saved Chromium profile** — it passed Google's browser-security check (Google OAuth to archive.org completed with the developer's 2FA; archive.org authenticated; sessions persisted in the profile after clean close — cookie store verified `accounts.google.com`/`.google.com`/`archive.org` rows on 2026-11-16 23:14) and cleared JSTOR's Client Challenge. By contrast a mismatched Firefox/core pairing hit Google's "This browser or app may not be secure"; the browser check is build-pairing-sensitive, which is why the default must name the specific channel and profile, not "a persistent browser".
- **Root Cause / Motivation.** The deck's `playwright-cli` skill card states provisioning (vendored Node, install runbook) and session hygiene (snapshot-first, close-when-done) but names **no default channel, no default profile doctrine, and no default headless/headed posture** — so every composing session improvises, and the improvised form (bare `open` → chrome channel; headless; ephemeral default profile) is exactly the form the walls defeat and the form that discards login state. The research skill (`skills/research/SKILL.md`) likewise carries no browser-first posture: it dispatches search/fetch sub-agents and never says when a real browser is obligatory, so sessions fall back to curl/API-first attempts against JS-rendered, bot-walled sites and only reach playwright if ever. Developer directives this session make both gaps explicit mandates.
- **Approach Chosen.** Land the default doctrine in the deck's `playwright-cli` card and its provisioning runbook — default launch = `--browser msedge --persistent` against a durable saved profile (the `ud-bl-persist` Chromium profile at the daemon cache path), headed by default for interactive web surfaces — plus the login-once flow that plants cookies into that profile, with named non-default paths (API-clean headless checks; `.tools/` browser provisioning when the channel is absent; per-site channel displacement when a particular site demonstrably works better under a different browser) instead of improvised alternates; and land the corresponding browser-first posture sentence set in the research card (playwright browser sessions used as needed, preferred over curl for most sites, per the default-channel doctrine). Developer directives, 2026-11-16 (verbatim): "file a spec. playwright needs to default to using edge + saved profile so that saved logins work."; "the research skill need to clearly indicate to use playwright ms edge as needed and to assume it should be used in preference to curl for most sites"; "it is acceptable to install browsers into the ignored .tools/". Developer directive, 2026-11-17 (verbatim): "msedge does not need to be the default if other browsers work better for a particular site or sites."
- **Alternatives Considered & Why Discarded.** (a) Headless UA spoofing / anti-detection patches — rejected: unreliable against Cloudflare-class and Google checks, brittle to their updates, and the observed evidence is that a headed real-channel browser is what passes. (b) Firefox as the default — rejected on observed 2026-11-16 evidence: the custom playwright Firefox build pairing triggers Google's OAuth browser rejection; the pairing sensitivity makes it a poor default. (c) Per-project throwaway profiles plus saved storage-state JSON files — rejected: the developer's directive is a saved profile that carries logins; state files add ceremony, drift, and per-site re-planting. (d) System-level browser installation — rejected: the sanctioned install target is the gitignored per-project `.tools/` tree (the vendored-tooling precedent — the runbook already provisions Node there, per `.tools/node/`), developer directive 2026-11-16: "it is acceptable to install browsers into the ignored .tools/"; system-package/`/opt` installs and improvised alternate channels stay out. On the observed machine msedge is already present, so provisioning is the absent-machine path of record, not this machine's path. (e) msedge as a site-unconditional mandate — rejected per developer directive 2026-11-17: browsers other than msedge serve particular sites where they demonstrably work better; the default stands, the per-site mandate does not.
- **Key Design Decisions.** (1) The channel+profile pairing is stated as one unit — the pairing (real Vendor Chromium + one durable profile) is what passes the checks; defaults are stated, never left to per-session judgment. (2) The saved profile is shared across sessions, not per-project: logins planted once must be visible to every later session — the daemon-cache path (`~/.cache/ms-playwright/daemon/ud-bl-persist`) is the profile of record. (3) Credentials never enter the deck: the login-once step is developer-performed in the headed window; the card documents the flow, never credentials. (4) curl is not banned — the research card's preference is "most sites"; clean JSON APIs (search/metadata endpoints like archive.org's `advancedsearch.php`) remain legitimate direct calls; the card states the posture, the plan-stage wording decides the split sentence. (5) The default carries its exception as stated doctrine, not per-session discretion — msedge + the durable profile is the default launch, and the card states the per-site channel exception (a particular site served by a different browser that demonstrably works better there); the exception is site-scoped and observation-bound, never a wholesale channel downgrade, and every site without such an observation keeps the default.
- **User Intent / Original Prompt.** Developer statements, 2026-11-16 (verbatim): "file a spec. playwright needs to default to using edge + saved profile so that saved logins work." · "the research skill need to clearly indicate to use playwright ms edge as needed and to assume it should be used in preference to curl for most sites" · (preceding observed-failure session, same day: repeated bot-wall losses under default launches; "you are supposed to use playwright as a part of your research so that you don't have all these fucking bot blockers"; "why aren't you using the fucking persistent profile so that fucking login to jstor etc fucking works?"; Edge + saved-profile login completed by the developer with the report "logged in")

## 2. Not Included

- **Browser installation outside `.tools/`** — provisioning targets only the gitignored `.tools/` tree (R-2d, vendored-tooling precedent). System-package installs, `/opt` targets, and un-shepherded install time (any install not run through the runbook's documented provisioning path) stay out of scope.
- **Credential handling** — the flow documents the developer-performed login window; the deck never touches or stores credentials (unchanged floor boundary).
- **JSTOR / archive.org / site-specific recipes** — the cards are site-agnostic; the 2026-11-16 working evidence lives in the research card of record, not in skill text.
- **Firefox / chromium-for-testing profile migration or cleanup** — the `ud-default-firefox`, `ud-aqv15-*`, and `ud-default-chrome-for-testing` profiles stay as found; no retirement mechanic.
- **Other cards' curl references** — the developer directive scopes the research card and the playwright-cli card; no sweep of other surfaces.

## 3. Requirements

R-1. The `playwright-cli` skill card SHALL state the default browser-session launch as one pairing: Microsoft Edge channel (`--browser msedge`) + durable persistent profile (`--persistent --profile ~/.cache/ms-playwright/daemon/ud-bl-persist`), headed for interactive web surfaces; headless and throwaway-profile launches SHALL appear only as documented, explicitly non-default fallbacks for API-clean checks. The card SHALL state the default's per-site channel exception in the same doctrine: msedge is the default, not a per-site mandate — where a particular site demonstrably works better under a different browser, that browser serves that site, as a named, observation-bound deviation rather than an improvised alternate channel.

R-2. The `playwright-cli` provisioning runbook (`references/install.md`) SHALL carry, consistent with R-1: (a) the msedge-presence check; (b) the default launch command; (c) the login-once flow (headed window on the target site, developer signs in, cookies land in the durable profile and persist across sessions); (d) the absent-channel path: provisioning a vendor browser build into the gitignored `.tools/` tree and pointing the channel at it (the runbook carries the recipe, mirroring its vendored-Node pattern), never an improvised alternate channel and never a system-level/system-package install.

R-3. The `research` skill card SHALL state the browser-first posture: playwright sessions per the R-1 channel-and-profile doctrine (the default pairing and its per-site channel exception) are used as needed for web research, and are assumed in preference to curl/raw page fetches for most sites; direct API calls remain appropriate for clean JSON endpoints. The card SHALL NOT leave browser usage as an undocumented, per-session discretionary step.

R-4. The profile of record SHALL remain the live, login-bearing one — the doctrine SHALL NOT name a fresh profile path that would discard the 2026-11-16 planted Google/archive.org sessions; where the card cites a path it cites the live one.

## 4. Precondition (evidence base)

## 6. Approach

Card-content changes to three deck surfaces (`playwright-cli/SKILL.md`, `playwright-cli/references/install.md`, `research/SKILL.md`) implementing R-1..R-4, then execution of the SC-4/SC-5 behavioral instruments against the live machine. Skill-card edits follow the deck's own governance path at implementation time.

## 7. Edge Cases

- **Concurrent sessions on the shared profile** — a Chromium persistent profile locks to one live browser; the card's existing close-when-done hygiene plus the documented launch flow cover it; no additional criterion.
- **Fresh machines without the planted logins** — SC-5's precondition is the 2026-11-16 profile state; on a fresh machine the runbook's login-once flow (R-2c) is how the profile gains state; SC-5 is evaluated where the precondition holds.
- **Absent msedge** — the R-2d provisioning path applies: install a vendor browser build into the gitignored `.tools/` tree per the runbook recipe and point the channel at it; absence is a provisioning trigger, never a spec failure and never license to improvise another channel (the per-site channel exception answers observed site function, not channel absence).
- **Per-site channel deviation** — the durable profile's planted logins are bound to the default channel's profile store; a site served under a deviating browser runs on that browser's own profile and inherits none of them. Where such a site needs authentication, the R-2c login-once flow is the flow of record in that browser's profile, and the session weighs that cost in the per-site choice.
- **Profile of record drift** (daemon cache reorganization) — R-4 binds the doctrine to the live path; a future path change is a revision of the card text, not a silent divergence.

## 8. Impact

- **Consumers.** Every session in every consuming repo doing web research (research-card dispatches; playwright-cli launches) acquires the default posture; bot-wall losses and login-state discards stop being per-session reinventions.
- **Surfaces.** Three deck files (R-1..R-3); no code, no tooling, no other cards.
- **Risk.** Card-text drift between the three surfaces (mitigated: one pairing stated once, runbook references the card's default rather than restating variants); msedge absence on other machines (R-2d `.tools/` provisioning); shared-profile concurrent-launch lock (documented close-when-done); the per-site exception degraded into wholesale channel downgrade (mitigated: the exception is stated as site-scoped and observation-bound, and SC-1 checks its presence beside the default).
