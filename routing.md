# Routing Index

Before acting, match your current intent against these entries and the skill
descriptions the platform presents. Load only what matches. Descriptions —
not user phrasing — are the dispatch mechanism.

| When your intent is... | Load |
|---|---|
| about to modify files, or starting implementation | `work` gate → routes spec→plan→implement→PR, scaled to need |
| exploring or decomposing requirements before a spec exists | `explore` |
| creating or revising a specification document | `spec` |
| writing an implementation plan from an approved spec | `plan` |
| executing an approved plan, or making any change during the implementation cycle | `implement` — loads the implementation-workflow reference first |
| checking a deliverable against stated requirements before claiming completion | `verify` — single fresh-context reviewer, churn rule, bounded loop |
| branching | `git-workflow-branch` |
| committing / staging files | `git-workflow-commit` |
| opening or updating a PR / preparing work for review | `git-workflow-pr` |
| post-merge cleanup | `git-workflow-cleanup` |
| rebase/merge/cherry-pick conflicts | `git-workflow-conflict` |
| creating, commenting, linking, or closing issues | `issues` |
| operating GitHub / GitBucket / the browser / notebooks | the matching connector card (`gh-cli`, `gb-cli`, vendor hf card, `playwright-cli`) |
| creating or modifying CI — pipelines, runners, workflows, or submodule checkout configuration | `ci-boundary` |
| discovering information or investigating root causes | `research` / `systematic-debugging` |
| designing, reviewing, or auditing code | `programming-principles` |
| authoring a plan or spec that references deck paths or dispatch strings, or acting on an embedded routing reference that may be stale or dead | `reference-currency` — consuming side owns reference currency, remediate before continuing |
| creating or editing any file under `skills/`, `guidelines/`, `floor.md`, or `routing.md` | deck governance (`skill-creator`) — admission gate first |
| producing a changelog, version bump, tag, or GitHub release | the matching release-trio card |
| producing an operational runbook | `sre-runbook` |
| drafting stakeholder correspondence | `correspondence` |
| routing work to models by content modality | `multimodal-dispatch` |
| checking workflow correctness by machine — constraint solving, proofs, counterexamples, or plan generation/validation/grounding | `formal-tooling` |

Card origins: **deck-authored** (governed) · **vendor-generated** (referenced,
regenerated by the owning tool — `hf skills add` — never hand-edited) ·
**project-local** (outside this deck).
