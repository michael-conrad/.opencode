# Static-i18n reference

<!-- Provenance: adapted from CodeSigils/zola-skill v1.0.0 (6b279b3), workflows/i18n.md; .opencode#2666 R-6 Read-links -->

Use this workflow for an existing Zola site's language configuration,
translated content or section files, template translations, or language-aware
URL failures. It covers static Zola i18n only; do not promise translation,
locale detection, browser-state switching, or search-index behavior.

## Inspect

- Preserve the site's language policy. For a diagnosis-only request, propose a
  minimal patch; apply one only when the request asks for the change.
- Read `default_language`, `[languages.<code>]`, `[translations]`, and
  `[languages.<code>.translations]` in the active configuration. Inspect
  language-suffixed content and `_index.<code>.md` files, relevant templates,
  and `base_url`.
- Determine `zola --version`, then Read [the source-registries
  reference](source-registry.md) multilingual and template entries before
  changing language configuration, filename rules, `trans`, or `get_url`
  behavior.

## Diagnose and repair

Use the configured language code exactly. A translated content filename must
use a configured language; Zola does not invent a fallback. When a translated
page is inside a section whose default file is `_index.md`, require that
section's `_index.<code>.md` before proposing a translated page repair.

In templates, use the active `lang` for translations and generated links when
the output must follow the current language, for example
`trans(key="nav_about", lang=lang)` and
`get_url(path="@/about.md", lang=lang)`. Preserve a non-root `base_url`; do
not replace generated URLs with hard-coded root-relative paths.

## Validate

1. Inspect the configured output directory and use a fresh isolated output
   directory for fixture-like builds; do not add `--force` by default.
2. Run `zola check --skip-external-links` and `zola build` with the relevant
   project root. Report that skipped external links were not checked.
3. Confirm the translated route includes its language prefix and inspect the
   generated link under the configured `base_url`.
4. For an expected configuration/content failure, preserve the fixture and
   assert the failure in both check and build rather than treating it as a
   successful repair.
